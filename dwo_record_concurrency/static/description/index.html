Record Concurrency Guard for Odoo

Stop one user from silently overwriting another.

Choose the models and fields that matter. When someone saves a record while you are editing the same fields, you see what changed and you decide what to do.

In Odoo the last save wins: if two people edit the same record, the second one silently erases the first one's changes. This module adds a safety net on the form view. It never blocks a save and never refuses a write on the server: it only shows the conflict and lets the user choose.

What you get

You choose what to watch

For each model, pick the fields to protect, from Settings > Technical > Concurrency. Models that are not configured are not affected at all.

Checked when you save

At save time the fields you edited are compared with the values they had when you opened the form. This also works if the live notification never reached your browser.

Only real conflicts

If another user changed a field you did not touch, nothing is shown. You are only interrupted for the fields you are actually saving.

Compare and decide

A table shows Your Updates next to the Latest Data, and who saved last. Choose Force Save, Discard My Updates or Cancel.

Live warning

While you edit, a notification tells you that another user has just changed fields you are editing, so you are not surprised at save time.

Every way of saving

The Save button, the pager, leaving the form and the automatic save are all covered. A tab in the background keeps your changes instead of overwriting anything.

Many field types

Text, numbers, dates, selections, many2one and many2many values, and binary fields are compared. Relational values are compared by record, not by order.

Several tabs, several users

The tab that saves is not warned about its own change. Other tabs, and other users, are told that the record changed.

Private by design

The live notification only says who changed which fields. It carries no field value, and a user can only listen to the records he is allowed to read.

How it works

Set it up once, then it works in the background.

1. Configure

Open Settings > Technical > Concurrency > Model Concurrency (developer mode), create a line for a model and select the fields to watch.

2. Edit as usual

Users open and edit the form. If someone else saves a watched field, a notification appears.

3. Save and choose

On save, a conflict on a field you edited opens a dialog. Otherwise the save goes through as usual.

See the difference before you overwrite

Another user saved the same field. The dialog shows both values and who saved last, and the three choices.

A warning while you edit

A short notification tells you right away that someone changed fields you are editing. Nothing is blocked.

Choose the models and fields to protect

One line per model, with the fields to watch. Only stored, editable fields can be selected.

Requirements & Installation

The module depends on the standard base, web and bus modules and needs no external Python library.

The live notification uses the Odoo bus (websocket). Without it, conflicts are still detected when the user saves.

Install the module

1. Copy the dwo_record_concurrency folder into an add-ons path of your Odoo server.

2. Restart Odoo, activate developer mode and click Update Apps List in the Apps menu.

3. Search for Record Concurrency Guard and click Install.

Reload your browser page after installing so the new assets are loaded.

Choose what to watch

In developer mode open Settings > Technical > Concurrency > Model Concurrency and click New.

Select the model, then add the fields to watch. Only stored fields that are not read-only are offered.

Only administrators can change this configuration; every internal user can read it.

What it does not do

The check runs in form views. Lists edited inline, kanban cards, imports and external API writes are not interrupted.

It never blocks: a user can always choose Force Save, and the server never rejects a write because of a conflict.

Closing the browser tab with unsaved changes asks for confirmation when the record is known to have been changed by someone else.

Frequently Asked Questions

Does it lock records?

No. Nobody is prevented from opening or saving a record. A user is only warned and chooses what to do.

What if the other user changed a different field?

Nothing is shown. The dialog only appears for the fields you edited and that changed on the server since you opened the form.

Does it slow Odoo down?

Models without a configuration are not touched. The configuration is cached, so saving a record does not add a database query for it.

Does it change my data or my views?

No. It adds one small configuration model and changes nothing in your own models or views.

What happens if the live notification does not arrive?

The check at save time still works, because it compares the values with the server when you click Save.
