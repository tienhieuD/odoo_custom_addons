Approval Flow for Odoo

Draw the approval of any document instead of coding it.

Boxes are the states of the document, arrows are the buttons that move it. Click an arrow to say who can press it, how many approvals it needs and what else happens.

Most approval needs are the same: a document goes from draft to review to approved, different people can press different buttons, and sometimes two people must agree. This module lets an administrator draw that process for any model, with no code, and shows the status and history on the form.

What you get

A diagram, not a form

Drag boxes, drag a dot from one box to another to add an arrow. Curved arrows bend around boxes, labels stay readable and boxes cannot overlap.

Who can press a button

Users, groups, a user taken from the document, a Python-style expression or an Odoo domain. Add rules such as amount above 10000 to route a document to a different step.

Several approvals

One approval is enough, or one per approver line, or at least N. Waiting votes are shown on the form until the button goes through.

Works on what you have

Use the state field the model already has (for example purchase orders), or let the module keep its own state. A button can set the state, or call an existing method and check the result.

Cannot be bypassed

Protect the method an arrow calls, so that confirming a purchase order from the old button, the list or an RPC call goes through the approval. The module's own state cannot be written directly.

Extra actions

When a button is pressed: post a notification, send an email, update a field, or run a server action. A button can ask for a reason, for example when rejecting.

Status and history widget

The form shows the current state, the buttons the user may press and the history of every vote and move, in an Approval tab.

List view Action menu

Mark an arrow to appear in the list Action menu and press it for many selected documents at once. Documents it cannot be pressed on are skipped and reported.

Test before you trust

The Test button shows, for a document and a user, which buttons would appear and why the others are hidden.

How it works

Set up a flow once, then it works on the documents.

1. Create a flow

Open Approvals > Flows, choose a model and where the states come from. Add boxes and arrows in the designer.

2. Set the arrows

Click an arrow: choose the approvers, the number of approvals, rules and what happens when it is pressed.

3. Use it

Users press the buttons on the form or from the list. Every vote and state change is recorded in the log.

Draw the flow

A purchase approval with branches: small orders go to the leader, big ones to the manager and the director. Reject returns to Draft.

Waiting for the other approvals

One of two required approvals is recorded. The form shows who has voted and what is still missing.

Press a button for many documents

Arrows marked for the list view appear in the Action menu.

Choose who can press it

Approvers can be users, groups, a user on the document, an expression or a domain.

Requirements & Installation

The module depends on the standard base, web and mail modules and needs no external Python library.

The approver kind Same department and the notification emails need the matching Odoo apps (Employees, a mail server).

Install the module

1. Copy the dwo_approval_flow folder into an add-ons path of your Odoo server.

2. Restart Odoo, activate developer mode and click Update Apps List in the Apps menu.

3. Search for Approval Flow and click Install.

Reload your browser page after installing so the new assets are loaded.

Create your first flow

Open the Approvals menu, then Flows, and click New. Choose the model and whether the states are the module's own or come from a field of the model.

Add states with + State, drag the dot of a box onto another box to add a button, then click the arrow to set approvers and actions.

Only users in the group Approval Flow / Administrator can edit flows. A flow can be exported and imported as JSON.

What it does not do

A document follows one flow at a time. With several flows on a model, the first one whose Applies to filter matches is used. Two flows cannot approve the same document in parallel.

A button does not run by itself when a state is entered, and an arrow cannot loop back to its own box.

Protecting a method stops calls from the interface and RPC. Code running as superuser (sudo) is never blocked.

Frequently Asked Questions

Can small orders go to one step and big ones to another?

Yes. Draw two arrows from the same box and give each a rule, for example amount below 5000 on one and amount of 5000 or more on the other. Only the arrow whose rule matches is shown.

Can a rejected document go back to draft?

Yes. A button can go to any box, so Reject can lead to Draft or to a Rejected state with a Reopen button.

Does it replace the buttons of my model?

If a model has one flow, the native state buttons are hidden and replaced by the flow's buttons. With the main step set to call a method, the original button logic still runs, only after the approval.

Does it work with custom models?

Yes, any model that has a form view. Models with a state selection field can reuse it.
