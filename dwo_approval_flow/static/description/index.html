Dynamic Approval Workflow for Odoo

Draw the approval of any document instead of coding it.

Boxes are the states of the document, arrows are the buttons that move it. Click an arrow to say who can press it, how many approvals it needs and what else happens.

Most approval needs are the same: a document goes from draft to review to approved, different people can press different buttons, and sometimes two people must agree. This module lets an administrator draw that process for any model, with no code, and shows the status and history on the form. It is an add-on to the flow you already have: it does not rewrite your model, so the original buttons, methods and states keep working. It can also be the approval flow of a model that has none.

What you get

Does not change your flow

Combine it with the workflow a model already has: an arrow can call the original button, so Odoo still does the real work, after the approval. Other modules and customisations are not rewritten.

Or a brand-new flow

Models without a status can have their own states, kept by the module, so you can build the whole approval process from scratch with no code.

A diagram, not a form

Drag boxes, drag a dot from one box to another to add an arrow. Curved arrows bend around boxes, labels stay readable and boxes cannot overlap.

Who can press a button

Users, groups, a user taken from the document, a Python-style expression or an Odoo domain. Add rules such as amount above 10000 to route a document to a different step.

Several approvals

One approval is enough, or one per approver line, or at least N. Waiting votes are reported until the button goes through. Buttons can also appear in the list Action menu for many documents at once.

Cannot be bypassed

Protect the method an arrow calls, so that confirming a purchase order from the old button, the list or an RPC call goes through the approval. The module's own state cannot be written directly.

Extra actions

When a button is pressed: post a notification, send an email, update a field, or run a server action. A button can ask for a reason, for example when rejecting.

Status and history

The form shows the flow's states and buttons, and every move is posted in the chatter. The Log menu lists every vote and move, and a history panel can be added to any form view.

Test before you trust

The Test button shows, for a document and a user, which buttons would appear and why the others are hidden.

How it works

Set up a flow once, then it works on the documents.

1. Create a flow

Open Approvals > Flows, choose a model and where the states come from. Add boxes and arrows in the designer.

2. Set the arrows

Click an arrow: choose the approvers, the number of approvals, rules and what happens when it is pressed.

3. Use it

Users press the buttons on the form or from the list. Every vote and state change is recorded in the log.

Step 1. Start from the form you already have

This is a purchase order as Odoo ships it. We will add an approval step before the order can be confirmed, without touching how the order itself works.

Step 2. Create the flow

Open Approvals > Flows > New, give it a name, choose the model and tick Replace the form's status bar if you want the flow's states to be shown instead of the original ones. Leave it unticked to keep the original bar.

Step 3. Draw the states and buttons

Add boxes with + State and drag the dot of a box onto another one to add a button. Here: Submit, then Approve or Reject, and Reopen to start again.

Step 4. Choose who can press it

Click the Approve arrow and choose the approvers: users, a group, a user on the document, an expression or a domain. Choose how many approvals are needed.

Step 5. Reuse the button you already have

Make the arrow call the method of the original button, here button_confirm. The order is confirmed by Odoo itself, only after the approval. If the result is not what the flow expects, everything is undone.

Step 6. The form now shows the flow

The status bar shows the states of the flow. The buttons of the flow appear next to the original ones, which keep working.

Step 7. Submit for approval

After Submit the document waits in Manager approval. People allowed to approve see Approve and Reject, the others see nothing. Every move is written in the chatter.

Step 8. Approved, and Odoo confirmed the order

Approve moved the document to Approved and called the original Confirm method: the order is now a purchase order. Reject asks for a reason and Reopen sends it back to Draft.

Bonus. Press a button for many documents

Tick Also allow from the list view on an arrow and it appears in the Action menu. Documents it cannot be pressed on are skipped and reported.

Requirements & Installation

The module depends on the standard base, web and mail modules and needs no external Python library.

The approver kind Same department and the notification emails need the matching Odoo apps (Employees, a mail server).

Install the module

1. Copy the dwo_approval_flow folder into an add-ons path of your Odoo server.

2. Restart Odoo, activate developer mode and click Update Apps List in the Apps menu.

3. Search for Dynamic Approval Workflow and click Install.

Reload your browser page after installing so the new assets are loaded.

Create your first flow

Open the Approvals menu, then Flows, and click New. Choose the model and whether the states are the module's own or come from a field of the model.

Add states with + State, drag the dot of a box onto another box to add a button, then click the arrow to set approvers and actions.

Only users in the group Approval Flow / Administrator can edit flows. A flow can be exported and imported as JSON.

What it does not do

A document follows one flow at a time. With several flows on a model, the first one whose Applies to filter matches is used. Two flows cannot approve the same document in parallel.

A button does not run by itself when a state is entered, and an arrow cannot loop back to its own box.

Protecting a method stops calls from the interface and RPC. Code running as superuser (sudo) is never blocked.

Frequently Asked Questions

Can small orders go to one step and big ones to another?

Yes. Draw two arrows from the same box and give each a rule, for example amount below 5000 on one and amount of 5000 or more on the other. Only the arrow whose rule matches is shown.

Can a rejected document go back to draft?

Yes. A button can go to any box, so Reject can lead to Draft or to a Rejected state with a Reopen button.

Does it break the flow my model already has?

No. It adds to it. The original buttons and methods keep working: an arrow can call the original method (for example Confirm), so Odoo still does the work, only after the approval. If a model has exactly one flow, the original button that the flow calls is hidden in the states where the flow handles it, so users are not shown two ways to do the same thing.

Does it work with custom models?

Yes, any model that has a form view. Models with a state selection field can reuse it.

Can I build a brand-new approval process?

Yes. Choose a model, keep My own states and draw the states and buttons. The module keeps the state itself, so no change to the model is needed.
