Auto WebP Image Conversion for Odoo

Your website images, 25–35% smaller. Zero effort.

Install once — /web/image URLs are served as WebP to browsers that support it, with a built-in cache and a safe fallback.

Heavy images are one of the main reasons an online store feels slow. Auto WebP Image Conversion automatically converts the images that Odoo serves through /web/image (product photos, website images, logos…) to WebP — a modern format that is typically 25–35% smaller than JPEG or PNG at the same visual quality — so pages load faster, you use less bandwidth, and visitors stay engaged. There is nothing to configure to get started: install the module and it just works.

Key Features & Benefits

Works on /web/image

Every image served through /web/image is converted: product photos, website images, logos, attachments. JPEG, PNG, BMP and TIFF are supported. Static theme files and /web/content downloads are not touched.

Built-in Smart Cache

Each image is converted once and the result is stored in Odoo (ir.attachment). Next requests are served from the cache — no CDN or extra service needed.

Multi-Website Ready

Every Odoo website has its own on/off switch, quality setting and isolated cache. Change one site without touching the others.

Quality You Control

Choose a quality from 1 to 100 per website. The default of 85 is a good balance of file size and visual quality.

Self-Maintaining

Re-upload an image and a fresh WebP is generated automatically. Cache of deleted records is removed by Odoo's daily autovacuum. A one-click “Clear WebP Cache” button is also available.

Safe Fallback

Browsers without WebP support receive the original image. SVG, GIF (which may be animated) and already-WebP files are passed through unchanged. If a conversion fails, the original image is served.

How It Works

Four steps, all automatic — your templates and image URLs do not change.

1. Browser asks

The browser requests an image and announces Accept: image/webp.

2. Cache lookup

The module looks for an already converted WebP for this image, size, website and quality.

3. Convert once

On a cache miss the image is converted to WebP with Pillow and stored for next time.

4. WebP served

The response is returned as image/webp. Other browsers still get the original.

See It in Action

Open any image of your website in the browser and check the response in the developer tools: the Content-Type is image/webp.

Simple to Configure

Everything lives in one place: Settings → Auto WebP. The options apply to the website selected in the Settings page. Conversion is on by default, so most shops never need to change anything.

Auto WebP Conversion

Enable or disable per website with a single checkbox. Default: on.

WebP Quality (1–100)

Default 85. Changing it automatically resets the cache of that website only.

Clear WebP Cache

Asks for confirmation, then flushes the cache of the current website. Images are re-converted on the next request.

Built-in Install & Config Tests

Not sure the server is ready? The Test Install and Config section of the settings page checks it for you in one click, and tells you what to fix if something is missing.

Test Python Import

Runs Python inside the Odoo server: imports Pillow and encodes a test image to WebP. Success shows the Pillow version; a failure explains that the WebP encoder (libwebp) is missing.

Test WebP Image

Loads a real /web/image URL of your own Odoo server with Accept: image/webp. If the response is a WebP image, you get a green WebP Test Success message.

Requirements & Installation

The module needs Pillow with the WebP encoder (built on libwebp) on the machine that runs Odoo. Most Linux and Windows installs already have it. If it is missing, the module does not crash — it simply serves the original images and logs a warning.

Always install Pillow with the exact Python that runs Odoo (its virtualenv or the system Python), then restart Odoo. Installing into the wrong Python is the most common mistake.

Replace X.Y.Z with the Pillow version listed in the requirements.txt of your Odoo version, so Odoo keeps running with the Pillow release it was tested with. The official Pillow wheels already include WebP support.

Linux (Ubuntu / Debian)

sudo apt install -y libwebp-dev
sudo /path/to/python3 -m pip install --upgrade pip
sudo /path/to/python3 -m pip install --force-reinstall "Pillow==X.Y.Z"
sudo systemctl restart odoo

If pip reports externally-managed-environment, add --break-system-packages. Avoid --no-binary Pillow on Linux: the prebuilt wheel already includes WebP, and compiling from source is slow and can fail.

Docker

Add this to the Odoo image's Dockerfile, then rebuild the image and restart the container.

RUN apt-get update && apt-get install -y --no-install-recommends libwebp-dev \
    && pip3 install --force-reinstall "Pillow==X.Y.Z"

Windows

The official Pillow wheel for Windows already includes WebP.

pip install --upgrade "Pillow==X.Y.Z"

macOS (Intel)

brew install webp
/path/to/venv/bin/pip install --force-reinstall --no-cache-dir --no-binary Pillow "Pillow==X.Y.Z"

macOS Apple Silicon (M1 / M2 / M3 / M4)

Homebrew on Apple Silicon lives in /opt/homebrew/. Set the library paths explicitly, otherwise Pillow is built without WebP even though libwebp is installed. 

brew install webp
LDFLAGS="-L/opt/homebrew/lib" CPPFLAGS="-I/opt/homebrew/include" \
  /path/to/venv/bin/pip install --force-reinstall --no-cache-dir --no-binary Pillow "Pillow==X.Y.Z"

Verify it works

Run with the same Python as Odoo (or simply click Test Python Import in the settings):

python -c "from PIL import Image; import io; img=Image.new('RGB',(1,1)); out=io.BytesIO(); img.save(out,format='WEBP'); print('OK, bytes:', len(out.getvalue()))"
# Expected output: OK, bytes: 44

Frequently Asked Questions

Does WebP look different from the original?

At the default quality of 85 the difference is hard to notice for typical photos. PNG images with transparency keep their alpha channel. You can raise the quality per website if you need pixel-perfect output.

Will it slow down my server?

Only the first request for each image (and size) is converted. After that the WebP is served from the cache stored in Odoo.

What happens when I update an image?

The cache is tied to the version of the source image. After you upload a new image, a fresh WebP is generated on the next request — no action needed.

What if a visitor's browser does not support WebP?

The browser receives the original image unchanged. Conversion only happens when the browser announces WebP support.

What about animated GIF images?

GIF files are never converted, so animations keep working. The same applies to SVG and images that are already WebP.

Does it work with several Odoo websites?

Yes. Each website has its own toggle, quality and cache. Changing the settings of one website never affects another.

Where is the cache stored? Will I see extra attachments?

Converted images are stored as ir.attachment records named webp_cache:..., linked to the source record. They may therefore appear in the attachment list of that record. Use Clear WebP Cache to remove them at any time; they are re-created on demand.

I see KeyError: 'WEBP' in the Odoo log.

Pillow was installed without the WebP encoder. Follow the installation steps above for your platform, restart Odoo, then click Test Python Import to confirm.
