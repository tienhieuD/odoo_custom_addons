Secure Session Login

Protect the Odoo session, not only the login.

Lock the screen with a PIN after an idle time, end sessions that are idle or too long, warn people before the end, sign out when the browser is closed, and let an administrator approve new sessions. The lock is kept on the server: a locked session cannot call anything, even with the browser developer tools open.

Live demo: demo-session.duotek.io.vn (Sign in as demo_alice, password demo; the lock PIN is 1234.)

A password protects the door; Secure Session Login protects the room when somebody leaves it. After an idle time the screen locks and a PIN (4 or 6 digits, chosen in Preferences) opens it again, on the same screen. The state of every session (active, locked, waiting for approval or ended) is stored on the server and checked on every request. The lock page is a plain page drawn by the server: it does not load the Odoo web client and holds no record.

A lock page without the application

When the screen locks, the browser leaves the web client for this page, drawn like the Odoo login page (it loads only its CSS). Typing the last digit of the PIN unlocks it, no button needed. It carries no menu, no record and no Odoo script, so the developer tools show nothing of the screen you left. Reload it, open the address in another tab or press Back: you get this page again until the PIN is entered.

Forgot the PIN? You choose the ways out

Each way is a switch in Settings: the account password or a new sign in (SSO and two-factor users go through the normal login page), a request to an administrator, a 6-digit code by email, or a temporary PIN from an administrator. After every way the user chooses a new PIN.

A code by email, a new PIN

The code (6 digits, valid 10 minutes, 3 per hour) opens the form to choose a new PIN. The field sends the code by itself when the sixth digit is typed.

Choose a new PIN

After every way to recover a PIN, the user chooses a new one: 4 or 6 digits, not an easy one, not the previous one. The second field saves it by itself when it matches the first.

The session ended: a dialog, then back to the same screen

When the idle time or the maximum duration is over, the page hides the screen and shows this dialog. The button opens the login page; after the sign in you are back on the screen you were on (only internal addresses are accepted).

A warning before the end, with a countdown

The warning appears a number of minutes before the end (30 by default, you can change it or switch it off). The Extend button adds time when the administrator allows it.

Approve new sessions

For the users you choose, a correct password is not enough: they wait on this page until an administrator approves, and Odoo opens by itself when that happens. Nothing of Odoo can be called while they wait.

Requests for the administrators

Session approvals and PIN reset requests arrive in one list. Approvers are told by a pop-up in Odoo, by email or by an activity, as you choose; every decision is logged.

Every open session, and a button to close it

User, IP address, browser, sign-in time, last activity and state. Select sessions and press Force sign-out: the session file is removed and the user sees the Session ended dialog. Each user can see and close their own sessions from Preferences.

All the rules in one Settings screen

Idle lock, idle sign-out, maximum duration, the warning, closing the browser, PIN length and tries, the ways to recover a PIN, session approval and the notification channels. A master switch turns everything off at once.

Each user chooses a PIN in Preferences

4 or 6 digits, confirmed with the account password. The PIN is stored as a salted hash; nobody, administrators included, can read it. Easy PINs (0000, 1234, 1990, repeated digits) are refused.

What you get

Lock screen with a PIN

After the idle time you set, the screen locks. The PIN is only for unlocking a session that is already signed in: it can never sign anybody in.

Idle and maximum time

End the session after an idle time and after a maximum duration since the sign in, both checked by the server, with a group of users that is exempt.

Warning before the end

A pop-up with the minutes left, 30 minutes before by default, on or off, with an Extend button you can allow or not.

Close the browser, sign in again

The session cookie is a browser-session cookie and the server watches a heartbeat of the tabs, so a browser that is closed and opened again asks for the password.

Session approval

A switch, off by default: chosen users wait for an administrator after the sign in. Toast, email or activity tell the approvers; decisions are logged; requests expire.

Ways to recover a PIN

Account password or sign in again, a request to an administrator, a code by email, a temporary PIN: each one on or off, all logged, with limits against abuse.

Sessions and a log

A list of the open sessions with a Force sign-out button, a list of requests, and a log of locks, unlocks, wrong PINs, resets, approvals and sign-outs.

Same screen after the sign in

The address you were on is kept (on the server for a lock, in the link for an expiry). Only internal paths are accepted, so the link cannot send people to another site.

Enforced on the server

A lock that only covers the screen can be taken off with the browser tools. This one does not live in the browser.

Every request is checked

While a session is locked, waiting for approval or ended, the server refuses RPC calls, pages, files, images and websocket connections. Only the lock page, the waiting page, the PIN forms and the sign out are allowed.

No application in the lock page

The web client leaves for a server-drawn page, clears its IndexedDB and Cache Storage, and reloads when the Back button brings an old page back. Signed-in HTML and JSON answers are sent with no-store.

The PIN is protected

Salted hash (the same method Odoo uses for passwords), no read access for any group, easy PINs refused, a pause after 3 wrong PINs and a sign out after the limit you set (5 by default). Forms carry a CSRF token.

Safe by construction

A new sign in gets a new session record, the return address is checked, an administrator is never asked for approval, and a system parameter switches every rule off if somebody is locked out.

Limitations

What to expect, so there are no surprises.

What is already on the screen

Data that the browser loaded before the lock cannot be recalled. The module leaves the page and clears the caches it can reach, but a person who stops the script of the page before it leaves (developer tools, an extension) keeps what was on screen. After the lock the server answers nothing.

Closing the browser

The server cannot see a browser close. It sees that no tab sent a heartbeat or a goodbye for the grace time (3 minutes by default). A browser that restores its tabs and cookies and is opened again within that time keeps the session, and a laptop that sleeps for longer than the grace time ends the session.

Idle time is measured in the browser

Mouse, keys and scroll in the page. A script can fake them, but it can never go beyond the maximum duration. Background calls of Odoo do not count as activity.

Unsaved forms

When the screen locks, a form that has not been saved is lost, unless you switch on the option to try to save it first (off by default, because the lock often comes when nobody is there to confirm). A form that cannot be saved is lost anyway.

Requirements & Installation

The module depends on the standard web, mail and bus modules. It needs no external library.

  • Install
  • If somebody is locked out

Install the module

1. Copy the dwo_session_security folder into an add-ons path of your server.
2. Restart Odoo and update the apps list.
3. Install Secure Session Login.

Set it up

Open Settings, then Secure Session. Defaults: lock after 15 minutes, sign out after 4 hours idle, maximum 12 hours, warning 30 minutes before, closing the browser ends the session. Each user sets a PIN in Preferences, Security; users without a PIN are not locked.

Every user can always sign out and sign in again. To switch all the rules off at once, set the system parameter dwo_session.enabled to 0 (Settings, Technical, System Parameters, or in the database). Administrators are never asked for a session approval, and the group Session security: exempt from time limits removes the time limits for chosen users.

Frequently Asked Questions

Can somebody open the developer tools and read the screen I locked?

The browser leaves the page when the lock starts, and the server refuses every call afterwards, so nothing new can be read. What was already loaded in the page before it left cannot be recalled by any web module: see Limitations.

Can the PIN sign somebody in?

No. It only unlocks a session that is already signed in. The password, SSO and two-factor stay the way to sign in.

What about users who sign in with SSO or two-factor?

Forgot the PIN sends them to the normal login page, so the whole sign in (SSO, two-factor) happens again, then they choose a new PIN.

Does it work with several tabs?

Yes. Locking one tab locks the others, and unlocking one opens the others. The idle time counts the activity of every tab.

Can an administrator read a PIN?

No. Only a salted hash is stored and no group has access to it. An administrator can give a temporary PIN (if you allow it) that the user must change at once.

Does the lock page work on a phone?

Yes, it is a small responsive page.
