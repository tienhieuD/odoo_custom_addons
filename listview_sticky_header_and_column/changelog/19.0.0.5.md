# 19.0.0.5

Module `listview_sticky_header_and_column` (Odoo 19.0). Previous version: `19.0.0.4`.

- Fixed: in an editable list, opening a Many2one dropdown (or any autocomplete) from a row was
  getting visually covered by the pinned/frozen column cells of the rows below it, even though
  the dropdown itself has a much higher `z-index` (web's own `.o-autocomplete--dropdown-menu`).
  Browsers give `position: sticky` table cells their own compositing layer, and sibling sticky
  cells with equal `z-index` can end up painted above a nested, absolutely-positioned child with
  a higher `z-index`. Fixed by raising the *edited* row's own pinned-column cell above every
  other row's (`tr.o_selected_row`, the class Odoo already applies to the row being edited), so
  the dropdown is lifted along with it. No new JS state (no "is a dropdown open" tracking needed).
- Found and verified with the `lab/listview_sticky_test_lab` test bed ("Editable list" action,
  Customer column pinned and edited, row 6 of 80).
