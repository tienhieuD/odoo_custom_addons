# 19.0.0.3

Module: `listview_sticky_header_and_column` (Odoo 19.0). Previous version: `19.0.0.2` (read `19.0.0.2.md` first
for how the module works). Only `static/src/js/main.js` changed.

## Problem
In a form with several lists (x2many fields), pinning a column in one list pinned the columns of ALL lists
and the remembered column was shared.

## Causes
1. The injected `<style name="listview_sticky_header_and_column">` used global selectors
   (`.o_content .table-responsive ...`), so it matched every list on the page.
2. `lshcRemoveOldStyle()` removed every `<style>` with that name, so one list erased the style of the others.
3. The `localStorage` key was `..__viewId_<viewId>` only, so lists of one form shared one saved column.

## Fix
- Each `ListRenderer` instance gets `this.lshcUid` (module level counter `lshcUidCounter`, set in `setup()`).
- In `lshcFreezeColumnListView()` the root element gets `data-lshc-id="<uid>"` and all CSS is prefixed by
  `scope = .o_content .table-responsive[data-lshc-id="<uid>"]` (same specificity as before or higher).
- Both `<style>` nodes carry `data-owner="<uid>"`; `lshcRemoveOldStyle()` removes only the nodes of its own
  renderer (also disconnects its own `ResizeObserver`).
- Storage key: `lshcGetFieldSuffix()` appends `__field_<name>` taken from
  `rootEl.closest('.o_field_widget[name]')` (the x2many field widget). Main list views have no such
  ancestor, so their key is unchanged (previously saved pins still work). x2many lists in a form now have
  their own key, e.g. `listview_sticky_header_and_column__viewId_123__field_line_ids`.
  The suffix needs the DOM, so it is only valid after mount (all callers run after mount).

## Notes / not verified
- Not tested in a browser by the agent. Test with a form that has 2+ x2many lists: pin in one, the other must
  stay unpinned; reload, each list must restore its own pin; unpin one only.
- Two lists in a form showing the same field twice would share a key (same `name`).
- Inside an x2many, `overflow: visible` on `.table-responsive` (inherited from 19.0.0.2) lets a table wider
  than the form overflow it; if that looks wrong, scope that rule to main lists only.

## Follow-ups in 19.0.0.3

- Crash on destroy (`TypeError: Cannot read properties of null (reading 'el')`): `lshcConfig()` built both
  keys eagerly and `viewKey` reads the DOM, which is gone in `onWillDestroy`. `lshcConfig` is now lazy
  (`'key'` returns the constant) and `lshcGetRootElement()` uses `bdom?.el || null`.
- x2many list lost its horizontal scrollbar after pinning: the `overflow: visible` rule on
  `.table-responsive` (needed only for main lists, scrolled by `.o_content`) is now skipped when the list is
  embedded in a form (`isEmbedded = el.closest('.o_field_widget[name]')`), so the renderer keeps its own
  `overflow: auto` and sticky `left` works against it.
