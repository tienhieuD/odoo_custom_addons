# 19.0.0.2

Module: `listview_sticky_header_and_column` (Odoo 19.0). Previous version: `19.0.0.1`.
Only `static/src/js/main.js` changed (function `lshcFreezeColumnListView`, `lshcRemoveOldStyle`).
No change to `main.scss`, `style.xml`, python or manifest dependencies (only `version` bumped).

## How the module works (needed to understand the changes)

- `main.js` patches `ListRenderer`. Each header `<th>` gets a pin button (`.js_pin_this_column`).
- Clicking pin stores the column index in `localStorage` (key `listview_sticky_header_and_column__viewId_<viewId>`;
  `-1` = unpinned) and calls `lshcFreezeColumnListView(columnIndex)`.
- That function injects `<style name="listview_sticky_header_and_column">` into `<head>`:
  1. `preStyles`: sticky header (`thead`, `top: 0`) + `overflow: visible` on `.table-responsive`
     (so sticky works against `.o_content` scroll).
  2. A second CSS block built per pinned column with `position: sticky; left: <px>` using
     `:nth-child(n)` on `th` / `tfoot td` / `tbody tr.o_data_row td`.
- `lshcRemoveOldStyle()` removes the style node (unpin, re-pin, destroy, re-mount).

## Problems fixed and how

### 1. Columns got wider after pinning (width not respected, drag-resize broken)
Cause: `preStyles` forced layout by content:
- `table { table-layout: auto !important }` (Odoo uses `fixed` with explicit `th` widths)
- `.o_data_row td { white-space: nowrap; padding: .3rem .75rem }` (removes ellipsis, widens columns)

Fix: removed both rules. Odoo keeps its own width computation and column drag & drop.
Only sticky related CSS remains. Keep `overflow: visible` on `.table-responsive`.

### 2. Pinned `left` offsets went stale after resizing a column
Cause: `left` was computed once at pin time.

Fix: the CSS is built by `buildCss()` and recomputed by a `ResizeObserver` observing the pinned
`th` (index `0..columnIndex`). The observer is stored in `this.lshcResizeObserver` and disconnected in
`lshcRemoveOldStyle()`. Changing `left` does not change widths, so there is no feedback loop.

### 3. Pinned area pushed far away from the left edge when pinning while horizontally scrolled
Cause: `left` was read from `th.offsetLeft`. For a sticky element `offsetLeft` is the scroll-shifted
position. `ResizeObserver` fires once right after `observe()`, when columns are already sticky.

Fix: `left` of column *i* = sum of `getBoundingClientRect().width` of pinned columns before it
(first = 0) in `buildStyles()`. Never use `offsetLeft` for this. Assumes the table starts at the
left edge of the scroll area.

### 4. Header / row colors differed from the theme
Cause: hardcoded `#eee` (header), `#eee`/`#ccc` (hover/focus), `#f9f9f9`/`#fff` (even/odd).

Fix:
- header: `background-color: var(--ListRenderer-thead-bg-color)` (Odoo variable, still opaque so
  scrolled text does not show through).
- removed hover/focus/zebra hardcoded rules, rows use Odoo's own colors.
- Sticky cells must stay opaque. Bootstrap paints a cell with `background-color: var(--table-bg)` plus
  `box-shadow: inset 0 0 0 9999px var(--table-bg-state, var(--table-bg-type, var(--table-accent-bg)))`
  (zebra/hover). Our own `box-shadow` (the border) would replace it, so the same `inset` shadow is
  repeated in our `box-shadow`. In Odoo `$variable-prefix` is empty, so the variables have no `bs-`.

### 5. Border of pinned columns
Final behaviour: only the **last** pinned column has the border: `box-shadow: -1px 0 0 #dee2e6 inset`
(left edge of that column), combined with the theme `inset` shadow above. Other pinned columns have
no border. Implemented with `index === pinnedColumns.length - 1` in `buildCss()`.

## Tried and rejected (do not retry blindly)

- Drop shadow on the right of the last pinned column (`box-shadow` outside the cell, higher `z-index`,
  or `::after` with `right: -8px` and `overflow: clip; overflow-clip-margin`). It never showed up in
  the UI. Odoo cells are `overflow: hidden` (`o-text-overflow`) and the real cause was not confirmed.
- Right border `inset -1px 0 0` on the last column: did not show up in the user's UI.
- Real `border-right` does not work: the table uses `border-collapse: collapse`, so borders belong to the
  table and do not follow a sticky cell. That is why the border is an inset `box-shadow`.

## Porting to another Odoo version

1. Check that `ListRenderer` still exposes `rootRef`, `setup()`, and that `th[data-tooltip-delay="1000"]`
   still identifies sortable headers (also used by `static/src/xml/style.xml`).
2. Check that `--ListRenderer-thead-bg-color` and `--table-bg`, `--table-bg-state`, `--table-bg-type`,
   `--table-accent-bg` still exist (grep `web/static/src/views/list/list_renderer.scss` and
   `web/static/src/scss/bootstrap_overridden.scss` for `$variable-prefix`).
3. Do not reintroduce `table-layout: auto`, `white-space: nowrap` or hardcoded colors.
4. Test: pin a column, drag-resize a column before/inside the pinned area, pin while scrolled
   horizontally, hover/focus rows, zebra rows, unpin, switch view.
5. Bump `version` in `__manifest__.py` and add a new file in `changelog/`.
