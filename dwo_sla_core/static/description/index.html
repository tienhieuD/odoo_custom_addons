SLA & Escalation for Odoo

Service Level Agreements, Operational Level Agreements and escalation chains — on any model, not just support tickets.

Define commitments once with point-and-click conditions, and let the engine measure, pause, breach and escalate them automatically, in real working hours, with a full audit trail and ten built-in reports to see how you are doing.

Most SLA tools only watch one kind of record: a helpdesk ticket. Enterprise SLA & Escalation Engine is built differently — it watches any model in your Odoo database. Sales orders stuck in approval, manufacturing orders behind schedule, expense reports awaiting validation, onboarding tasks, vendor commitments: if it is a record in Odoo, you can put a measurable, time-bound commitment on it. Every rule is pure configuration — domain conditions, a target duration and a working calendar — so your implementation team defines new SLAs without writing a line of Python. The engine runs in the background, attaches, pauses, resumes, completes and escalates tasks automatically, and keeps a complete, tamper-evident event log explaining every decision it made. Key Features & Capabilities

Model-Agnostic by Design

Point an SLA Definition at any Odoo model through its six conditions: Start, Stop, Pause, Resume, Cancel and Reset. The engine snapshots the rule when a task attaches, so editing a definition later never changes tasks already running.

Enable When You Are Ready

A new definition starts disabled, so you can finish and review it first. One Enable button turns it on, Disable stops it attaching to new records while running tasks finish, and a ribbon and a list toggle show which is which.

Apply to Existing Records

Turn an SLA on after the fact: Apply to Existing Records attaches it to the records that already match, with an optional extra filter. The first batch runs at once, larger sets continue in the background, and every run is listed on the definition.

Real Working-Hour Calculations

Durations are measured against a working calendar (business hours), not the wall clock — a 4-hour SLA opened Friday at 16:00 does not breach over the weekend, and holidays defined on the calendar are skipped too. No calendar selected means a straightforward 24/7 clock instead.

SLA and OLA in One Model

Classify each definition as a customer-facing SLA or an internal Operational Level Agreement, optionally tie it to a Vendor for underpinning contracts, and flag it as an officially published Service Commitment for reporting.

Multi-Stage Escalation, Zero Setup

Chain as many percentage thresholds as you need — a 75% warning, a 100% breach notice, a 150% director alert. Each stage emails a responsible person out of the box, or runs a standard Odoo Server Action for custom automation.

Retroactive Start & Pause

Backdate the SLA start to a date already on the record (for example its creation time) instead of the moment the rule was configured, and credit any backdated period that was already on hold — reconstructed from the record's own change history.

Per-Rule Timezone

Every definition has its own timezone, which always wins over the timezone of the working calendar. Reuse one calendar across regions without touching the original: the engine keeps a hidden copy of it in the timezone you chose.

Status On the Record Itself

A status chip in the top bar of every record under an SLA shows the worst running task at a glance: time left, a progress bar and a red state the instant it is breached — no separate screen to check, no code. An optional smart button adds the count of active and breached tasks.

Ten Built-in Reports

A Reporting menu with ten ready-made screens: compliance trend, response-time distribution, status mix, open backlog and ageing, performance by definition and by source, pause analysis, escalation activity, source heatmap and calendar impact. Read-only, for SLA Users and Managers.

Colours That Mean Something

In the charts, On Time is always green, Late orange, Breached (Open) red, Running blue-grey, Paused light grey and Cancelled grey, whatever the grouping, and the trend chart's rate axis stays between 0 and 100%.

Filters for Every Question

Open, Breached Open, Late, Last 30 Days, This Week, Due This Week, Response or Resolution, SLA or OLA — one click each. Group by outcome, usage range, week or month of start, end or deadline, then export the pivot to a spreadsheet.

From drafting a definition to the reports, all from the demo data of a small company: leads, support tasks and sales orders under 18 definitions. Pick a tab to jump to the part that matters to you: set-up first, then what you see on the records, then ten reporting screens.

One Commitment, One Definition

Each commitment is an SLA Definition: the model it applies to, SLA or OLA, the target, the duration, the working calendar and when to warn that it is due soon. The Start Condition is built with Odoo's own domain editor and the form tells you how many records match right now. Enable or Disable at the top lets you draft first and switch on when ready, and a Open Tasks button opens the tasks of the definition.

Stop the Clock While You Wait

The Pause/Resume Condition says when the clock stops and when it runs again. Here the clock stops while the task is in the Waiting state (waiting for the customer) and, with the resume mode When pause no longer matches, runs again as soon as that condition is no longer true. Retroactive Pause can also count the time the record spent waiting before the SLA attached, rebuilt from its change history.

Start Over When the Record Starts Over

The Reset Condition restarts the clock when a record goes back to the beginning. Here a quotation in the Quotation Sent status whose Expiration changes has its previous task cancelled and a new one started. Each change of the trigger field resets once, no more.

Remind and Escalate in Stages

The Escalation tab stacks as many percentage thresholds as the process needs. This rule emails the salesperson of the record at 75% and 100%, a fixed address at 100% and a manager's address at 150%. Each step can send an email template or run a standard Odoo Server Action, and fires once per task.

Turn an SLA On After the Fact

Apply to Existing Records attaches the SLA to the records that already match its Start Condition, with an optional extra filter, and tells you in advance how many records will be checked. The first batch runs at once, larger sets continue in the background, and each run is logged on the definition.

Time Counts in Working Hours

Deadlines follow a working calendar, not the wall clock. The Standard Hours calendar here is 40 hours a week, Monday to Friday, 08:00 to 12:00 and 13:30 to 17:30. With no calendar the clock runs 24/7. Each definition has its own timezone, which takes priority over the timezone of the calendar.

Holidays Are Skipped

Time off declared on the working calendar (Resource Time Off) does not count towards the deadline. This list shows four breaks of the Standard Hours calendar.

Deadlines That Skip Holidays

Deadlines That Skip Holidays

A 2-hour response started on Friday at 16:30 has one working hour left that day. Monday is a holiday on the calendar, so the deadline lands on Tuesday at 09:00 and the task finishes at 83% of its target.

Status on the Record, With No Code

Open any record that has an SLA: the form shows a status chip next to the pager with the time left or the overrun and a progress bar, and it turns red when a task is breached. Hover for each task. It shows to SLA users only, and can be switched off in the settings.

One Task, Its Progress and Its History

The built-in SLA Progress widget gives every task a status badge, a progress bar and the three milestones that matter — Start, Deadline, End. Past the deadline the bar stays full and the overrun is shown next to the percentage (here +158%); far past it, as a multiplier such as 7.0× instead of a four-digit number. The History tab lists every attach, escalation and breach with its timestamp.

Is the Achieved Rate Going Up or Down?

Finished tasks that started in the last 30 days, grouped by the week they ended and by definition, with the achieved rate on a 0–100% axis and one line per group. Here the lines are grouped by target, Response against Resolution, so a weak week for first replies stands out at once.

How Much of the Time Did Tasks Really Use?

Every finished task falls into a usage range of its target: 0–50%, 50–75%, 75–100%, 100–150% or over 150%. The chart opens on Response SLAs and stacks the ranges per definition, so a definition whose bars are mostly red has a target that is too tight, or a team that is too slow.

Where Do All Tasks Stand?

One pie of every outcome: On Time, Late (finished after the deadline), Breached (Open) for tasks that are past the deadline and still running or paused, Running, Paused and Cancelled. The colours are fixed, so a screenshot from last month still reads the same.

What Is Open, and How Old Is It?

A pivot of the open tasks: one row per definition, one column per week of the deadline, with the number of tasks and how many are breaching right now. Expand a definition to see the models behind it. The list view of the same screen is sorted by deadline and shows the share of the target already used.

Which Definitions, and Which Sources, Miss Their Targets?

Stacked bars of On Time, Late and Breached (Open) per definition. A sibling screen, Performance by Source, does the same per model, and the Source Heatmap lays achieved rate out by model, definition and month.

How Often Did the Engine Step In?

Events per week: breach, escalate and, when an action fails, escalate failed. The Pause Analysis screen next to it totals the hours tasks spent on hold, per definition, in business hours and in clock hours.

Clock Time Versus Working Time

For finished tasks, the pivot puts the plain Duration next to the Business Duration and the paused hours (clock and business). A definition on a 24/7 clock shows the same figure twice; one on office hours shows how much of the clock time never counted.

How It Works

Six conditions, evaluated by a background job every minute — no polling to configure, nothing to schedule.

1. Define

Pick a model and write the Start and Stop Conditions, a target duration and, optionally, a working calendar. A new definition is a draft until you press Enable.

2. Attach

The moment a record matches the Start Condition, a task is created and the clock starts — immediately, or retroactively from a date on the record. Records that already exist can be attached with Apply to Existing Records.

3. Track

A background job checks every running task once a minute: pause when the Pause Condition matches, resume when it stops matching, and recompute the deadline against the working calendar.

4. Escalate

Each configured percentage threshold emails the right person once, or runs a custom Server Action — your choice per rule.

5. Close

When the Stop Condition matches, the task closes as Achieved or Breached; the Cancel and Reset conditions handle records that leave scope or change shape mid-flight.

Built for Governed Environments

Two access groups and a complete read-only audit model, so SLA reporting can be opened up without any risk to the underlying rules.

SLA User vs. SLA Manager

Users can read tasks and events to answer “why is this late?”. Only Managers can edit SLA Definitions, trigger a manual re-evaluation or mark an error event resolved.

Every Action Server-Side

Escalation Server Actions always run with the permissions of the background job's own user, never with the permissions of whoever last edited the source record.

Requirements & Installation

Pure configuration, no external services and no library to install — the engine runs entirely inside Odoo on the standard base, resource, web and mail modules.

Retroactive Pause reads the target model's own change-tracking history (mail.thread), so it only has an effect on models and fields that already log changes in Odoo — the configuration screen tells you clearly when that is not the case for a given rule.

The background job runs once a minute as a standard Odoo scheduled action (ir.cron); no cron, queue or worker needs to be set up outside Odoo.

Install

Copy the module into your addons path and install it like any other Odoo app — from the Apps list, or from the command line.

./odoo-bin -d your_database -i dwo_sla_core --stop-after-init

Create your first SLA

Go to SLA → SLA Definitions → New, pick a model, write a Start Condition, a Stop Condition and a Duration, then save and press Enable. The next record that matches gets its own SLA Task automatically — no restart needed. For records that already exist, press Apply to Existing Records.

Grant access

Add the users who should only read tasks and events to the SLA / User group, and the users who configure rules to SLA / Manager, from Settings → Users.

Upgrading from the first release

An empty condition, including the empty domain, now means “not configured” and never matches (the domain editor still labels it “Match all records”). On upgrade, an empty Start Condition is rewritten to [('id', '!=', 0)], so tasks that were running are not cancelled.

A definition created from the form now starts disabled; one created by code or import must set active=True. The timezone of a definition is required and always wins over the timezone of the calendar: the upgrade fills it from the fixed calendar, or UTC.

Calendar copies made for a timezone share the public holidays of the original at the time of the copy and do not follow later changes to it.

Frequently Asked Questions

Does this only work with Helpdesk tickets?

No. An SLA Definition points at any model in your database through its Model field — sales orders, manufacturing orders, project tasks, expense reports, or a fully custom model. Helpdesk needs no special integration.

What happens if I edit a rule while tasks are already running?

Nothing changes for tasks already attached: the duration, calendar and conditions are captured as a snapshot the moment a task attaches. Only new tasks created after the edit use the new configuration.

Why does a new definition start disabled?

So you can finish the conditions and review them before any record is touched. Press Enable when you are ready. Definitions created by code or import must set active=True.

Do records that existed before I enabled the SLA get a task?

Not by themselves. Press Apply to Existing Records on the definition: it attaches the SLA to the records that match the Start Condition and skips the ones that already have a task.

What does an empty condition mean?

“Not configured”: it never matches, even though the domain editor labels the empty domain “Match all records”. To mean every record, write a rule that is always true, for example [('id', '!=', 0)].

Which timezone is used when the calendar has its own?

The one on the definition. It is required and always wins over the timezone of the calendar; when they differ, the engine uses a hidden copy of the calendar in the timezone you chose.

Can one record have more than one SLA at the same time?

Yes. Create one SLA Definition per commitment — for example a Response SLA and a separate Resolution SLA on the same model — and a record that matches both gets two independent tasks.

How is “breached” decided when there is no working calendar?

With no calendar selected, the engine counts plain 24/7 clock time. With a calendar selected, only working hours count towards the target, so time outside business hours never counts against the deadline.

What does a percentage threshold like 150% actually mean?

100% is the exact deadline. A 150% threshold fires once the task has consumed one and a half times its target duration — useful for a final escalation well after the SLA itself has already breached.

What happens if an escalation action fails?

It is logged once as a failed event with the error message, visible on the Unresolved Error Events screen, so an administrator can fix the configuration. It does not retry automatically.

Is the background processing heavy on the database?

The scheduled job only looks at tasks that are due for a check in the next run and locks each row briefly while it updates it, so it scales with the number of currently active SLAs, not with your whole database.

Can I report on SLA performance without building a dashboard?

Yes. The SLA → Reporting menu has ten ready-made screens (trend, distribution, status mix, backlog, performance, pause, escalation, heatmap and calendar impact), and SLA Tasks ship with List, Pivot and Graph views including an Achieved Rate and a Currently Breaching measure, so you can filter, group and export straight away.
